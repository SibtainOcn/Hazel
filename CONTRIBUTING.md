# Before You Begin

If you are already familiar with tools like `yt-dlp`, you know how they operate: lightweight command-line utilities written in Python designed to fetch video and audio content across thousands of sites. Our project aims to provide that same core functionality.

### Reporting Issues & Requesting Features
Before opening a new ticket, please perform a quick search across both open and closed issues to ensure your topic hasn't already been addressed. 

If no existing thread covers your problem or idea:
1. Choose the appropriate issue template.
2. Provide as much detail as possible to help us reproduce or understand your request.

*Note: Submissions missing required template fields or sufficient context may be closed without review.*

### Questions & Community Support
For general questions, feature suggestions, or casual discussions:
* Open a thread in **GitHub Discussions**



## Feature Requests
Hazel is designed to serve strictly as a streamlined interface for yt-dlp, mirroring its existing features directly without adding standalone capabilities. Because of this focus, we cannot accept feature requests for functionality that yt-dlp itself does not support.

## Bug Reports
Please provide enough detail in your bug report so we can easily replicate the issue. Be sure to include your custom command or options, the target video URL, and all required details listed in the template. Attaching a quick screen recording is also highly encouraged to help us spot the issue faster.

## Pull Requests
Before submitting code directly to the repository, please leave a comment on the relevant issue or open a new one outlining your proposed changes. This helps ensure alignment with the project before you begin writing code.

## Building from Source
Fork this project, import and compile it with the latest version of Android Studio Canary.

## AI Contribution Guidelines

Using Generative AI tools is completely acceptable, but we expect all contributors to maintain high standards of quality, accountability, and legal compliance. By submitting AI-assisted work, you accept full ownership of the submitted content and guarantee that no copyrighted third-party material is involved.

### 1. Mandatory Code Understanding
* You are fully accountable for every single line of code submitted to **Hazel**.
* Do not submit AI outputs that you cannot explain or justify during review.

### 2. Rigorous Local Validation
* Every PR must be built, compiled, and executed locally before submission.
* Verify that all new changes pass existing test suites without breaking core functionality.
* Never use our automated CI pipeline as your primary testing ground for unverified code.

### 3. Clear & Honest Disclosure
* Explicitly mention in your PR description if AI generated a major portion of your implementation.
* Briefly detail which components (such as specific modules, complex algorithms, or test suites) were AI-assisted.

### 4. Legal & License Safety
* Confirm that the AI platform you use respects open-source licensing constraints.
* Ensure you possess the legal authority to license and release the output under the official [Hazel License](LICENSE).

### 5. Refinement & Code Polish
* Filter out unnecessary boilerplate, redundant methods, and excessive inline comments generated by AI.
* Format and style the generated code so it strictly conforms to Hazel's existing codebase standards.



## Testing & Quality Verification

Before submitting a Pull Request, ensure that all quality checks / tests pass.

**Failure to follow these guidelines may result in your Pull Request being closed without review.**
